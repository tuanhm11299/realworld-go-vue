# M7 · Vue shell

**Tests:** `.specs/e2e/health.spec.ts`, `.specs/e2e/auth.spec.ts`,
`.specs/e2e/navigation.spec.ts`

**Goal:** a real SPA shell — navbar, routing, auth state, and an API client
every other view can build on.

## Why this milestone exists

The frontend has its own contract, and it is unusually literal: the e2e suite
locates things by CSS class and `name` attribute. `.specs/e2e/SELECTORS.md` lists
every one. Treat it as an interface definition, not a style guide — and read it
before you write markup, not after a test fails.

## Build

1. **`src/api/client.ts`** — the fetch wrapper. One place that prefixes `/api`,
   attaches `Authorization: Token <jwt>` (note: **Token**, not Bearer), reads the
   body once, and throws a typed `ApiError` carrying the `{errors:{field:[msg]}}`
   payload. It must survive a response that is not JSON at all — a 502 from a
   proxy is HTML, and `user-fetch-errors.spec.ts` checks you do not explode.

   Decide: does the client read the token from the Pinia store (a cycle), or does
   the store inject it (the client knows nothing about Pinia)? Write down why.

2. **`src/stores/auth.ts`** — state (`user`, `token`), getters
   (`isAuthenticated`), actions (`login`, `register`, `restore`, `updateUser`,
   `logout`). `restore()` runs before the first render, from `main.ts`. A stored
   token may be expired or forged, so verify it with `GET /api/user` rather than
   trusting localStorage. Wrap every localStorage access in `try/catch` — it
   throws in some privacy modes.

3. **`src/App.vue`** — the navbar and footer, on every page:
   `nav.navbar` containing `a.navbar-brand`, and `a.nav-link` items that switch
   between the logged-out set (Home / Sign in / Sign up) and the logged-in set
   (Home / New Article / Settings / *username*). Markup to copy lives in the
   upstream templates doc under `.specs/realworld/docs/`.

4. **Login and Register views** — the exact field names from `SELECTORS.md`, a
   submit that disables while in flight, and `ul.error-messages` rendering the
   server's 422. Write the `{errors:{field:[msg]}}` → `string[]` mapping once, in
   a helper, and reuse it on every form for the rest of the project.

5. **Route guards** in `src/router/index.ts`. `/settings`, `/editor` and
   `/editor/:slug` redirect anonymous visitors to `/login`. Guard in
   `router.beforeEach`, not in a component's `onMounted` —
   `url-navigation.spec.ts` navigates by typing URLs, and by the time a component
   mounts you have already rendered.

Delete each `TodoPanel` usage as you replace it.

## Questions to answer in writing

- A guard protects the UI. What stops someone calling your API directly? (Nothing
  — unless the backend checks too. Confirm yours does.)
- The token lives in localStorage, readable by any script on the page, so one XSS
  steals it. What would httpOnly cookies change, and what new problem would they
  bring? You will implement the alternative in Stage H of the roadmap.
- `restore()` makes a network call before the first render. What does the user
  see while it is in flight, and what happens if it fails?
