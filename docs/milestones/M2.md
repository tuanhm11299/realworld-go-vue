# M2 · Authentication

**Tests:** `.specs/api/hurl/auth.hurl`, `.specs/api/hurl/errors_auth.hurl`

**Goal:** register, log in, read and update the current user — and build the HTTP
plumbing that every later endpoint reuses.

## Why this milestone exists

This is the biggest single jump in the course. You will build the router, the
middleware chain, the error contract and the security primitives, and every other
endpoint will be assembled from those pieces. Take the time to get the shapes
right; you will pay for a rushed `respond.go` for the next six milestones.

## Build

1. **`internal/auth/password.go`** — hash and verify. argon2id
   (`golang.org/x/crypto/argon2`) or bcrypt. If argon2id, encode the parameters
   into the stored hash so you can raise the cost later without invalidating
   existing passwords. Verification must take the same time for a wrong password
   as for an unknown email, or you have built an account-enumeration oracle.

2. **`internal/auth/jwt.go`** — issue and parse. The spec's header is
   **`Authorization: Token <jwt>`**, not `Bearer`. Reject `alg: none` and any
   unexpected signing method, and write a test that proves you do.

3. **`internal/httpx/respond.go`** — one place that writes JSON with
   `Content-Type: application/json; charset=utf-8`, and one place that maps
   errors to status codes:

   | Cause | Status |
   |---|---|
   | validation failure | `422` with `{"errors":{"field":["message"]}}` |
   | missing or invalid token | `401` |
   | authenticated but not permitted | `403` |
   | resource absent | `404` |

4. **`internal/httpx/middleware.go`** — RequestID, Logger, Recover, CORS,
   `Authenticate` (required) and `MaybeAuthenticate` (optional). Write them as
   `func(http.Handler) http.Handler` and compose them. The logger needs a
   `ResponseWriter` wrapper to capture the status; write it yourself and
   understand why it is necessary.

5. **`internal/httpx/router.go`** — Go 1.22+ `ServeMux` handles method and path
   patterns, so you need no dependency:
   ```go
   mux.HandleFunc("POST /users", h.Register)
   mux.HandleFunc("GET /articles/{slug}", h.GetArticle)   // r.PathValue("slug")
   ```
   Mount it in `main.go` under `/api`.

6. **The four handlers** in `internal/handler/users.go`.

`PUT /api/user` is the hard one. The suite distinguishes three cases per field:
a field that is **absent** (leave unchanged), a field set to **`""`** (normalise
an empty bio or image to null), and a field set to **`null`** (accept, for
nullable fields). `encoding/json` cannot tell "absent" from "zero value" with a
plain `string` field. Use `*string`, or `json.RawMessage`, or your own
`Optional[T]` — and be able to explain your choice. You will need the same
solution for `PUT /api/articles/:slug` in M4, so build it once and build it well.

## Questions to answer in writing

- What is inside your token, and what happens when that data changes? If you put
  the username in the claims and the user renames, what breaks?
- How would you revoke a token right now? (You cannot — which is why Stage H of
  the roadmap adds refresh tokens.)
- Your middleware puts the user in the request context. Why a typed unexported
  key rather than a string?
- Login with a wrong password and login with an unknown email must be
  indistinguishable. Is yours — including in timing and in your logs?

## Going further

- Add a rate limit to `/users/login`. What do you key it on, and what does that
  choice do to users behind one NAT?
- Fuzz your JWT parser: `go test -fuzz`. Feed it garbage and truncated tokens.
