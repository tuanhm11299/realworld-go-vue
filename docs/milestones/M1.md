# M1 · Schema and data layer

**Goal:** design the Conduit database, then generate a type-safe Go data layer
from your own SQL.

## Why this milestone exists

Every later decision inherits from the schema. A missing unique constraint
becomes a duplicate-account bug; a missing index becomes a production incident at
10× traffic. This is also the milestone where you decide whether you *own* your
SQL or delegate it to an ORM. This template chose to own it — sqlc reads your
queries and generates Go, so the SQL stays visible and the compiler still checks
the types.

## Build

1. **Design the schema** in `api/migrations/00001_init.sql` (currently empty on
   purpose). You need: `users`, `follows`, `articles`, `tags`, `article_tags`,
   `favorites`, `comments`.

   Decide these deliberately, and write an ADR for each in `docs/decisions/`:

   | Decision | Think about |
   |---|---|
   | `bigserial` vs `uuid` keys | Enumerable ids leak information; uuids cost index locality |
   | Email case sensitivity | `citext`, or a `unique index on lower(email)`? |
   | Timestamps | `timestamptz`, always. Find out what `timestamp` actually stores before you type it |
   | Deletes | `ON DELETE CASCADE`, or explicit deletes in a transaction? |
   | Self-follow | Can a row in `follows` have `follower_id = followee_id`? Stop it in the schema |

   Prefer several small migrations to one big one — you want practice rolling
   individual changes back.

2. **Write queries** in `api/internal/store/queries/*.sql`, grouped by aggregate.
   Start with what M2 needs: create a user, get by email, get by id, update.

3. **Generate** with `make sqlc` and read what came out. If it looks wrong, the
   fix is in your SQL, not in the generated file.

4. **Write the API types by hand** in `web/src/types/api.ts` while the payload
   shapes are fresh. Transcribing the contract is how you notice its sharp edges
   — particularly that list endpoints omit `body`, so a feed item and an article
   are genuinely different types.

## Verify

```bash
make migrate-up && make migrate-status
make migrate-down && make migrate-up     # your Down must actually reverse your Up
make sqlc && cd api && go build ./...
make psql                                 # then: \d+ articles
```

## Questions to answer in writing

- Which columns did you make `NOT NULL`, and which did you leave nullable
  because the *spec* says null (`bio`, `image`)? Nullable-by-accident is a bug
  source; nullable-by-contract is fine.
- `favorites` and `follows` are both join tables. What is their primary key, and
  what does that choice enforce for free?
- Which indexes do you predict the feed query will need? Write the prediction
  down now. M5 will tell you whether you were right.

## Going further

- Add a `CHECK` constraint that stops a user following themselves, then write
  the test that proves the database rejects it even if your Go code forgets.
- Load 100k articles with `generate_series` and look at `EXPLAIN` for a simple
  filter. You are not tuning yet — you are learning to read the plan.
