# M0 · Walking skeleton

**Goal:** understand what you were given, then make the two pieces of plumbing
that `cmd/api/main.go` deliberately left crude.

## Why this milestone exists

A "walking skeleton" is a thread through every layer of a system that does
nothing useful: it starts, connects to its database, answers a probe, and shuts
down. It is worth building first because it proves the *hard* parts of the setup
— networking, configuration, lifecycle — before any feature can hide a problem
in them.

You already have one. Read it before you extend it.

## Build

1. **Read `api/cmd/api/main.go` line by line.** Everything there is deliberate:
   - Why `Ping` at boot rather than on the first request?
   - Why are `/healthz` and `/readyz` different, and why does `/healthz` not
     touch the database?
   - Why `signal.NotifyContext` and `srv.Shutdown` rather than letting the
     process die?
   - Why is `run()` separate from `main()`? (Hint: try to test a `main`.)

2. **Build `internal/config`.** Move environment reading out of `main.go` into a
   typed, validated `Config`. Report *all* validation problems at once. Refuse to
   start in production with the development JWT secret.

3. **Get comfortable with the tooling.** Create a throwaway migration, apply it,
   check `make migrate-status`, roll it back, delete it. Break something on
   purpose — point `DATABASE_URL` at a closed port — and read the failure.

4. **Run the graders and look at what they say.**
   ```bash
   make verify-api    # 13 files, 13 failures
   make verify-web    # 139 tests, all failing
   ```
   Skim a Hurl file, say `.specs/api/hurl/auth.hurl`. It is readable prose. This
   is the specification you are implementing, in executable form.

## Verify

```bash
cd api && go build ./... && go vet ./... && go test ./...
make migrate-up && make migrate-status
make api            # then: curl localhost:8080/healthz ; curl localhost:8080/readyz
```

Send the running server a `SIGTERM` (Ctrl-C) and confirm you see
`shutdown complete` rather than an abrupt exit.

## Questions to answer in writing

- What is the difference between liveness and readiness, and what breaks if a
  load balancer polls the wrong one?
- `run()` returns an error and `main()` calls `os.Exit(1)`. Why not call
  `os.Exit` from inside `run()`? (Consider deferred functions.)
- Your config is read once at startup. What would it take to reload it without
  a restart, and is that worth it?

## Going further

- Add a `/version` endpoint reporting the git SHA, injected at build time with
  `-ldflags`. You will want this the first time you wonder what is deployed.
- Write a test for `internal/config` that does not mutate the real environment.
