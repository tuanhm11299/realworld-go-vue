# M8 · Feature parity

**Tests:** `.specs/e2e/articles.spec.ts`, `comments.spec.ts`, `social.spec.ts`,
`settings.spec.ts`, `url-navigation.spec.ts`, `null-fields.spec.ts`

**Goal:** every remaining view, until Conduit is a working application.

## Why this milestone exists

This is the broad, unglamorous middle of any product: many screens, each mostly
straightforward, with the difficulty hiding in state that has to survive a
refresh and in fields that are legitimately null.

## Build

**Home** (`HomeView.vue`) — the `.banner` hero for logged-out visitors, the
`.feed-toggle` tabs (Your Feed / Global Feed / a tag tab once a tag is picked),
`.article-preview` cards, the `.sidebar` tag list from `GET /api/tags`,
pagination at 10 per page, and `.empty-feed-message` when there is nothing.

Decide early **where feed state lives**. Which tab, which tag, which page: the
URL, the component, or the store? The e2e suite navigates by URL and reloads, so
anything that must survive a refresh belongs in the URL. This is the single
most consequential design decision in the frontend.

**Article** (`ArticleView.vue`) — `.article-page` with `.banner` and
`.article-content`, markdown rendered client-side, `.article-meta` appearing
twice (banner and footer) with follow and favourite buttons, Edit/Delete for the
author only, and comments: `.card` per comment, `.mod-options` delete only on
your own, a `textarea[placeholder="Write a comment..."]` for posting, and a
prompt to sign in instead of a form for anonymous visitors.

Markdown means rendering user input as HTML. Do not reach for `v-html` yet —
M9 is about exactly that, and `xss-security.spec.ts` is waiting.

**Editor** (`EditorView.vue`) — the four inputs, Enter-to-add tag pills each with
an `ion-close-round` remove button, `POST` with no slug and `GET`-then-`PUT`
with one. Navigate to the slug **in the server's response**, never the one you
had: changing the title changes the slug.

**Profile** (`ProfileView.vue`) — `.user-info` with avatar, username and bio;
Follow/Unfollow for others and Edit Profile Settings for yourself; two tabs that
are the same list with a different query parameter (`author=` vs `favorited=`),
each at its own URL. Watch the route param so `/profile/a` → `/profile/b`
actually refetches. Fall back to `/default-avatar.svg` when `image` is null.

**Settings** (`SettingsView.vue`) — prefilled form, logout button, and `PUT
/api/user` with **only the fields that changed** (you built the backend for this
in M2 — now build the client half). A blank password field means "unchanged",
not "set it to empty".

**Null fields** — `null-fields.spec.ts` exists because this goes wrong
constantly. A user with `bio: null` must see an empty textarea, not the string
`"null"`. An article with no tags must render no pills, not an empty pill.

## Questions to answer in writing

- Which pieces of state ended up in the URL, and which in the store? What was
  your rule?
- Favouriting from a feed card updates a count. Did you re-fetch the list,
  update the one item from the response, or optimistically update and reconcile?
  What does each do when the request fails?
- You now have several components fetching lists of articles. What did you
  extract, and what did you deliberately leave duplicated?
